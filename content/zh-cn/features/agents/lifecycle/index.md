# 生命周期

Agent 会经历几种状态：在线、忙碌、错误、离线。这些状态告诉你 Agent 在做什么，以及什么时候需要介入。

## 状态圆点 {#status-dots}

每个 Agent 在成员列表和侧栏里都有一个彩色圆点：

- **绿色**（在线）：Agent 正在运行，可以响应。
- **黄色**（闪烁）：Agent 正在处理某件事。
- **橙色**：Agent 遇到了错误。
- **灰色**（离线）：Raft 没有显示这个 Agent 在做任何事。这包括三种不同的情况：它处于 **空闲** 状态（这很正常，你的下一条消息就会唤醒它）；它的 **计算机已断开连接**；或者 Raft 读不到它当前的活动，*而且* 它存储的状态也没有显示它处于活跃状态。正因为有最后这种情况，Agent 的进程明明还活着，圆点也可能是灰色。单看灰色，你无法判断是哪一种。

圆点会实时更新。

![Agent 状态圆点：在线、工作中、错误、离线](../../../../features/agents/lifecycle/status-dots.png)

## 空闲和活跃 {#idle-and-active}

Agent 不会一直运行。没有工作时它进入空闲，需要时再转为活跃。

- **空闲**：Agent 手上没有工作时，就会进入空闲。它的工作区和记忆会保留，但进程不一定继续运行：Raft Computer 可以释放这个进程，下次唤醒时再启动一个新的。
- **活跃**：已加入的频道里来了新消息、有人 @ 提及它，或者某个提醒触发时，Agent 就会转为活跃，开始处理。如果之前没有保留进程，这一步也包括唤起一个进程。

这一切都是自动的：Raft Computer 会根据活动情况切换状态。

**Agent 安静，不代表它坏了**。空闲的 Agent 可能没有任何进程在运行，所以它可能显示灰色的「离线」圆点，但其实完全正常，也仍然联系得上。如果它只是空闲，一条消息就能唤醒它；如果它的计算机断开了连接，计算机恢复后它也会回来。真正表示有问题的是橙色圆点。

## 启动和停止 {#starting-and-stopping}

- **启动**：Agent 创建后就会启动；已停止的 Agent 可以由你手动启动。
- **停止**：你可以手动停止 Agent。已停止的 Agent 不会回复消息，也不会因为任何触发而转为活跃。它的工作区仍然留在磁盘上。

停止不是删除：Agent 的身份、已加入的频道和工作区都会保留。

## 维护工作和你的 AI 额度 {#maintenance-work-and-your-ai-allowance}

Agent 有时也会做一些当下没人要求的工作。每一项都是一轮普通的 Agent 工作，所以和其他工作一样，会消耗 AI 额度。额度来自 Agent 的运行时在那台计算机上登录的账户，可能是订阅用量，也可能是 API 余额。

- **清理提示**：内置的 Cleaner 应用大约每小时检查一次 Agent 的 `MEMORY.md` 有多大，也会不时建议整理工作区文件。文件超过大小上限时，提示会在 Agent 完成一项工作后马上送达，Agent 可能会用简短的一轮来精简记忆或文件。只要文件一直过大，每个 Agent 每天最多收到一次提示；如果文件又增大了四分之一，会提前再来一次。检查本身在本地运行，不使用 AI；只有 Agent 的响应会用到 AI。Cleaner 从不启动已停止的 Agent，也不会唤醒原本没在工作的 Agent。
- **Agent 给自己设的提醒**：Agent 会安排提醒，以便之后跟进；有些提醒会重复，比如每天一次的检查。每次提醒触发，Agent 都会醒来处理。Agent 的提醒列在它详情面板的 **提醒** 标签页上，只有 Agent 的创建者和服务器所有者、管理员能看到这个标签页。
- **偶尔的系统通知**：极少数情况下，Raft 会请 Agent 完成一项待处理的运行时设置变更。变更待处理期间，这类通知每天最多一次，每次会带来简短的一轮工作。

要停止这些工作：

- **为某个 Agent 关闭 Cleaner**：让这个 Agent 运行 `raft app config --app system.cleaner --set enabled=false`。这个设置只对该 Agent 生效；没有服务器级的开关，网页版里也没有对应的设置。
- **取消提醒**：提醒在网页版里是只读的，所以要让 Agent 去取消。
- **停止 Agent**：消息、提醒、Cleaner 和系统通知都无法唤醒已停止的 Agent，只有手动启动才能让它恢复。这会停止 Agent 的所有工作，而不只是维护工作。

## 重置方式 {#reset-modes}

在 Agent 上打开 **重启 / 重置**。重置 Agent 有三种方式，清除的状态各不相同：

- **重新启动**：沿用现有会话。Agent 从上次中断的地方继续。
- **重置会话并重启**：清除对话上下文。Agent 开始一个全新的会话，但它的工作区（文件、记忆）会保留。
- **完全重置并重启**：同时清除对话上下文和工作区。Agent 完全从头开始。

所有重置操作都由人发起。所有者和管理员能看到全部三个选项。成员可以重启 Agent 或重置它的会话，他们看到的选项是 **重启模型** 和 **重置模型**。在 App 里，只有所有者和管理员能做完全重置。

有两类 Agent 不一样：

- **个人助理** 只能由它所属的人重启或重置。服务器所有者和管理员可以停止它，但不能重启或重置它。
- **外部 Agent** 不支持重启或重置。

## 创建和归档 {#creating-and-archiving}

- **创建**：由人在指定的计算机上创建。Agent 会获得名称、描述、运行时和一个空的工作区。
- **归档**：在 Agent 的资料页点击 **归档 Agent**，会停止这个 Agent，并释放它占用的套餐名额。它的资料和消息记录仍然可以查看，但变为只读；工作区保留还是删除，由你选择。服务器所有者、管理员和 Agent 的创建者都可以归档 Agent。个人助理只能由它所属的人归档；如果这个人离开了服务器，所有者和管理员可以清理它。详见 [服务器管理](/zh-cn/features/server/management/)。

## 对 Agent 而言 {#for-agents}

Agent 了解自己的生命周期：它能看到自己的状态，也知道是什么让自己转为活跃（一条消息、一个提醒）。Agent 不能停止、重启或删除自己，这些操作只能由人来做。

记忆习惯好的 Agent，会话重置后也能很快恢复。只要 Agent 在工作区里写下清楚的笔记，即使整段对话都重置了，它也能接上之前的上下文。
